# Translations

A **translation** is identified by a **key** (a string your application uses to look up a piece of text) and exists once per locale. The **Translations** page lists every key in the project, one row per key, with a tag showing the status of each locale's translation.

<!-- screenshot: translations list with status tags per locale -->

## How translations get created

Translations are generated by calling the translation API with a key, source text, and one or more target locales (see [API access](/guide/api-access)) — this is normally done by your application at build time or on demand, not manually in the admin UI. When a request comes in for a key/locale pair:

- If an unchanged, completed translation already exists, it's returned from cache — no LLM call is made.
- If the source text has changed, or no translation exists yet, the LLM generates a new one.

This cache-vs-generate split is what the little chart icon and number on each row means (see [Usage & analytics](/guide/usage-analytics)) — it tells you how many requests for that key were served from cache versus how many triggered a fresh LLM call.

## Filtering and searching

Click **Filters** to narrow the list by key, status, source/target language, LLM provider or model, or locked state. Filters are reflected in the URL, so a filtered view can be bookmarked or shared. The search box in the top header searches across the whole project and jumps straight to a translation's detail page.

## Editing a translation

Click any row to open its detail page, which shows every locale's translation for that key side by side. From there you can:

- **Edit the text directly** and save — this marks the translation as human-edited (`generated_by: user`) so it won't be silently overwritten by a later automated request unless the source text also changes.
- **Regenerate** a single locale, forcing a fresh LLM call even if nothing changed.
- **Add a locale** the key doesn't have yet, without leaving the page — see below.
- **View history** — every edit, whether from a person or the LLM, is kept as a version you can review.

### Adding a locale to an existing key

If a key has translations for some locales but not others, use the **Add locale** control on its detail page: pick a locale from the dropdown (only locales that don't already have a translation for this key are listed) and click **Add locale**. It reuses the key's existing source text and context tags and generates the new translation immediately.

## Locking

Lock a key (from the list or the detail page) to protect it from being overwritten — locked keys are skipped by regeneration, bulk regenerate, and import. Useful for translations that have been manually reviewed and approved, or where an automated pipeline shouldn't touch the text again.

## Bulk actions

Select multiple rows with the checkboxes to **regenerate** or **delete** several keys at once. Locked keys are silently skipped rather than blocking the whole batch.

## Export and import

**Export** downloads every translation (one row per key/locale pair) as CSV or JSON. **Import** upserts from a file in the same format — a row for a locked translation is skipped, and imported rows are attributed to a human edit rather than the LLM. See [Bulk operations](/guide/bulk-operations) for the difference between import and bulk-translating a whole locale.
