# Projects

A project is the top-level container for a single app or product's translation work — its own locales, translations, context tags, glossary, LLM configuration, and API keys all live inside it.

## Creating a project

From the **Projects** list, click **New Project** and give it a name. There's nothing else required up front — locales are seeded automatically, and you can configure an LLM provider whenever you're ready to start generating translations.

## Switching projects

Use the project switcher at the top of the sidebar to move between projects you have access to. The sidebar remembers the last project you visited, so returning to the app after account-level pages (like Account Settings) takes you back to where you left off.

## Renaming a project

Go to **Settings → General** and update the name. This doesn't change the project's internal ID or affect any existing API keys.

## Project access

Who can see and edit a project is controlled by **membership**, not just being on the same account — see [Account & team](/guide/account-and-team) for how roles and invites work. A user can be an admin on one project and a plain member (or have no access at all) on another, even within the same account.
